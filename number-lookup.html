01 / OVERVIEW

Built around a controlled workflow.

The application separates the public interface from server-side integration. That keeps upstream credentials out of browser code and makes access control a backend responsibility.

The current live link is configurable; replace it later if the deployment changes.

03 / STACK

Backend — serverless API routes

Data — Neon Postgres

Hosting — Vercel

04 / DECISIONS

Why it is structured this way.

Secrets stay server-side. Access is validated before the upstream request. User-facing output is kept separate from provider-specific credentials and fields.

05 / NOTES

What comes next.

Future iterations can improve observability, rate limiting, audit logs and UI polish while keeping the same separation of responsibilities.
