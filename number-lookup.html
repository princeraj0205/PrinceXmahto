01 / OVERVIEW

A cleaner project experience.

The portfolio page presents the project separately from the rest of the site, so the application can evolve without changing the main portfolio.

The production deployment is hosted independently. If its access configuration changes, this portfolio page does not expose or store credentials.

Backend — serverless API routes

Hosting — Vercel

Data — project-specific storage where required

04 / SECURITY

Credentials stay private.

Secrets should remain on the server and never be embedded in portfolio HTML, browser JavaScript or public links. Access should be limited to services and data the operator is authorised to use.

05 / STATUS

Deployment is separate.

The project button points to the separate deployment without embedding any access token. If that deployment is currently unavailable or its access has been revoked, the portfolio remains fully usable.

PROJECT NOTE

Designed for
future updates.

The project page is intentionally independent from the application itself. That makes it easy to replace the deployment URL, add documentation or publish a safe demo later.

Only use lookup services with data and systems you are authorised to access.
